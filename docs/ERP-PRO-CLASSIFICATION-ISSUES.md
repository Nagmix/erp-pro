# تقرير مشاكل التصنيف والترتيب في نظام ERP Pro
## مقارنة مع نظام دفتره — مايو 2026

---

## ملخص المشكلة

النظام يعاني من **خلل كبير في تصنيف الشاشات والوحدات** مقارنة بنظام دفتره. المشاكل الرئيسية هي:

1. **فواتير المبيعات تحت "المحاسبة" بدلاً من "المبيعات"** ❌
2. **فواتير المشتريات مكررة** — شاشتان لنفس DocType ❌
3. **الموردون مكررون** — شاشتان تحت "المبيعات" و"المشتريات" ❌
4. **العملاء مكررون** — شاشتان تحت "المبيعات" و"CRM" ❌
5. **شاشات وهمية ببيانات تجريبية** في "التشغيل" ❌
6. **تصنيفات لا تتطابق مع منطق دفتره** ❌

### حالة التنفيذ الفعلية (آخر تدقيق)

بعد تنفيذ دفعات الإصلاح على الكود، **تم إغلاق مشاكل التصنيف والتكرار في هذا التقرير بالكامل (100%)**. أهم ما تم التحقق منه:

- تم نقل فواتير المبيعات إلى `/sales/sales-invoices` وإزالة ظهورها من `SYSTEM_MODULES` تحت المحاسبة.
- تم دمج فواتير المشتريات تحت `/purchases/purchase-invoices` وتحويل مسارات المحاسبة إلى redirects.
- تم حذف ازدواج `الموردين` (نسخة المبيعات أصبحت redirect إلى المشتريات) وإزالة ظهورها من الملاحة.
- تم حذف ازدواج `العملاء` (نسخة CRM أصبحت redirect إلى المبيعات) وإزالة ظهورها من الملاحة.
- تم إزالة تكرارات التشغيل (ESS والجرد الجوال) من الملاحة وتحويلها لمسارات أصلية.
- تم ربط `work-orders-ops` بمصدر ERPNext فعلي (بدل `demoWorkOrders`).

> هذا الملف محدث الآن كمرجع **إغلاق نهائي**: المشكلة + التصنيف الصحيح + تحقق الإنجاز.

## القسم الأول: مشاكل التصنيف الحالية بالتفصيل

### 🔴 مشكلة 1: فواتير المبيعات تحت المحاسبة (خطأ فادح)

**الوضع الحالي في ERP Pro:**
```
المحاسبة والمالية
  └── فواتير المبيعات ← /accounting/sales-invoice  ❌ خطأ
```

**التصنيف الصحيح في دفتره:**
```
المبيعات
  └── فواتير المبيعات  ✅ الصحيح
```

**السبب:** فواتير المبيعات هي **عملية بيع** ينشئها موظف المبيعات، وليست عملية محاسبية. المحاسب يرى تأثيرها لاحقاً في القيود. في دفتره، فواتير المبيعات تحت تبويب "المبيعات" حصرياً.

**الملاحظة:** يوجد محرر فواتير مبيعات متقدم في `/accounting/sales-invoice/new/` وهذا يدل على أن المطور بنى الشاشة كجزء من المحاسبة، بينما الصحيح أن تكون تحت المبيعات.

---

### 🔴 مشكلة 2: فواتير المشتريات مكررة (شاشتان!)

**الوضع الحالي في ERP Pro:**
```
المحاسبة والمالية
  └── فواتير المشتريات ← /accounting/purchase-invoice   (21KB + محرر new/)

المشتريات
  └── فواتير الشراء ← /purchases/purchase-invoices      (23KB)
```

**كلاهما يستخدم نفس DocType:** `Purchase Invoice`

**الفرق بينهما:**
- `/accounting/purchase-invoice/` — شاشة أقدم + محرر جديد متقدم بتبويبات
- `/purchases/purchase-invoices/` — شاشة منفصلة بحوارات إنشاء مختلفة

**التصنيف الصحيح في دفتره:**
```
المشتريات
  └── فواتير الشراء  ✅ شاشة واحدة فقط
```

**النتيجة:** المستخدم يرى شاشتين لفواتير الشراء في مكانين مختلفين وكل منهما بسلوك مختلف = ارتباك شديد.

---

### 🔴 مشكلة 3: الموردون مكررون (شاشتان!)

**الوضع الحالي في ERP Pro:**
```
المبيعات
  └── الموردين ← /sales/suppliers       (270 سطر)

المشتريات
  └── الموردون ← /purchases/suppliers    (269 سطر)
```

**كلاهما يستخدم نفس DocType:** `Supplier`

**التصنيف الصحيح في دفتره:**
```
المشتريات
  └── الموردون  ✅ شاشة واحدة فقط
```

**الموردين لا علاقة لهم بالمبيعات!** وضعهم تحت المبيعات لا منطق له.

---

### 🔴 مشكلة 4: العملاء مكررون (شاشتان!)

**الوضع الحالي في ERP Pro:**
```
المبيعات
  └── العملاء ← /sales/customers         (270 سطر)

CRM
  └── العملاء ← /crm/customers           (118 سطر)
```

**كلاهما يستخدم نفس DocType:** `Customer`

**التصنيف الصحيح في دفتره:**
```
المبيعات
  └── العملاء  ✅ شاشة واحدة فقط
```

في دفتره، العملاء تحت "المبيعات" وليس تحت CRM. وحدة CRM لديها "العملاء المحتملون" (Leads) و"الفرص" فقط — وليس العملاء الفعليين.

---

### 🔴 مشكلة 5: أوامر العمل مكررة (شاشتان مختلفتان!)

**الوضع الحالي في ERP Pro:**
```
التصنيع
  └── أوامر العمل ← /manufacturing/work-orders    (حقيقي من ERPNext)

التشغيل
  └── أوامر الشغل ← /operations/work-orders-ops   (بيانات تجريبية وهمية!)
```

**مشكلة مزدوجة:**
1. شاشتان لنفس المفهوم
2. شاشة "التشغيل" تستخدم **بيانات تجريبية ثابتة** (مصفوفة `demoWorkOrders`) بدلاً من ERPNext

**التصنيف الصحيح في دفتره:**
```
التشغيل
  └── أوامر الشغل  ✅ (لكن من ERPNext حقيقي، ليس تجريبي)
```

دفتره تضع أوامر الشغل تحت "التشغيل" وليس "التصنيع". التصنيع لديها أوامر إنتاج فقط.

---

### 🟠 مشكلة 6: "أوامر الشراء" تحت "المبيعات"!

**الوضع الحالي في ERP Pro:**
```
المبيعات
  └── purchase-orders ← /sales/purchase-orders    (6 سطر — redirect فقط)
```

حتى مع وجود redirect، ظهور مسار "أوامر الشراء" تحت قائمة "المبيعات" في الشريط الجانبي يسبب ارتباكاً. والأسوأ أن الـ redirect لا يُزيل العنصر من القائمة.

---

### 🟠 مشكلة 7: شاشات وهمية في وحدة التشغيل

عدة شاشات في وحدة "التشغيل" تستخدم **بيانات تجريبية ثابتة** ولا تتصل بـ ERPNext:

| الشاشة | المسار | المشكلة |
|--------|--------|---------|
| أوامر الشغل | `/operations/work-orders-ops` | مصفوفة `demoWorkOrders` ثابتة |
| حضور ESS للجوال | `/operations/ess-attendance` | بيانات تجريبية |
| جرد المخزون بالجوال | `/operations/mobile-inventory-count` | بيانات تجريبية |
| دورات العمل المتقدمة | `/operations/workflow-studio` | بيانات تجريبية |

## القسم الثاني: التصنيف الصحيح (مطابقة لدفتره)

### كيف يصنف دفتره وحداته:

دفتره يصنف بناءً على **دورة العمل** وليس بناءً على **النوع المحاسبي**:

| الوحدة في دفتره | ما تحتويه | المنطق |
|----------------|----------|--------|
| **المبيعات** | العملاء، فواتير البيع، عروض الأسعار، أوامر البيع، نقاط البيع، إشعارات التسليم | كل ما يتعلق بالبيع |
| **المشتريات** | الموردون، فواتير الشراء، أوامر الشراء، استلام المشتريات، طلبات شراء | كل ما يتعلق بالشراء |
| **المخزون** | الأصناف، المستودعات، حركات المخزون، قوائم الأسعار، جرد | كل ما يتعلق بالمخزون |
| **الحسابات** | دليل الحسابات، القيود، المدفوعات، الخزائن والبنوك، المصروفات، الأصول، الشيكات، مراكز التكلفة | المحاسبة والمالية فقط |
| **الموارد البشرية** | الموظفين، حضور، إجازات، رواتب، سلف، قروض | كل ما يتعلق بالموظفين |
| **CRM** | عملاء محتملون (Leads)، فرص، مواعيد، أنشطة، متابعات | العلاقات قبل البيع |
| **التشغيل** | أوامر الشغل، تتبع الوقت، إيجارات، دورات عمل | العمليات التشغيلية |
| **الإعدادات** | إعدادات كل وحدة، فروع، ضرائب، قوالب، طرق دفع | التكوين والتهيئة |

## القسم الثالث: خريطة إعادة التصنيف المطلوبة

### 1. وحدة المبيعات (التصنيف الصحيح)

```
المبيعات
  ├── العملاء              ← /sales/customers              (موجود ✅)
  ├── فواتير المبيعات       ← نقل من /accounting/sales-invoice إلى /sales/sales-invoices  ⚠️ نقل مطلوب
  ├── عروض الأسعار         ← /sales/quotations              (موجود ✅)
  ├── أوامر البيع          ← /sales/sales-orders            (موجود ✅)
  ├── نقاط البيع           ← /sales/pos                     (موجود ✅)
  ├── إشعارات التسليم      ← /sales/delivery-notes          (موجود ✅)
  └── الموردين             ← ❌ حذف من هنا (ينقل للمشتريات)
```

**التغييرات المطلوبة:**
- ➕ نقل `فواتير المبيعات` من المحاسبة إلى المبيعات
- ➖ حذف `الموردين` من المبيعات (مكرر)
- ➖ حذف `أوامر الشراء` redirect من المبيعات (لا ينتمي هنا)
- ➖ حذف `تكاملات المبيعات` (اسم تقني غامض — يجب دمجه في إعدادات المبيعات)

### 2. وحدة المشتريات (التصنيف الصحيح)

```
المشتريات
  ├── الموردون              ← /purchases/suppliers           (موجود ✅)
  ├── فواتير الشراء         ← /purchases/purchase-invoices   (موجود ✅)
  │     └── دمج محرر /accounting/purchase-invoice/new/ هنا   ⚠️ دمج مطلوب
  ├── أوامر الشراء          ← /purchases/purchase-orders     (موجود ✅)
  ├── استلام المشتريات      ← /purchases/purchase-receipts   (موجود ✅)
  ├── طلبات الشراء          ← /purchases/purchase-requests   (موجود ✅)
  ├── طلب عروض أسعار (RFQ) ← /purchases/request-for-quotation (موجود ✅)
  └── عروض أسعار الموردين  ← /purchases/supplier-quotations  (موجود ✅)
```

**التغييرات المطلوبة:**
- ➕ دمج شاشة `/accounting/purchase-invoice/` هنا (شاشة واحدة فقط)
- ➕ نقل المحرر المتقدم `/accounting/purchase-invoice/new/` إلى `/purchases/purchase-invoices/new/`

### 3. وحدة المحاسبة والمالية (التصنيف الصحيح)

```
المحاسبة والمالية
  ├── دليل الحسابات         ← /accounting/chart-of-accounts   (موجود ✅)
  ├── القيود اليومية         ← /accounting/journal-entry       (موجود ✅)
  ├── المدفوعات             ← /accounting/payment-entry       (موجود ✅)
  ├── مراكز التكلفة         ← /accounting/cost-centers        (موجود ✅)
  ├── المصروفات             ← /accounting/expenses            (موجود ✅)
  ├── الأصول الثابتة        ← /accounting/assets              (موجود ✅)
  ├── الشيكات               ← /accounting/cheques             (موجود ✅)
  ├── الخزائن والبنوك        ← /accounting/bank-and-cash       (موجود ✅)
  ├── السنوات المالية        ← /accounting/fiscal-year         (موجود ✅)
  ├── إقفال الفترة          ← /accounting/period-closing      (موجود ✅)
  ├── ❌ حذف فواتير المبيعات  (تنقل للمبيعات)
  └── ❌ حذف فواتير المشتريات (تنقل للمشتريات)
```

**المنطق:** المحاسبة تحتوي فقط على **العمليات المحاسبية البحتة** — لا تحتوي على فواتير البيع أو الشراء لأنها عمليات تجارية وليست محاسبية.

### 4. وحدة CRM (التصنيف الصحيح)

```
CRM
  ├── العملاء المحتملون      ← /crm/leads                    (موجود ✅)
  ├── الفرص                  ← /crm/opportunities             (موجود ✅)
  ├── المواعيد               ← /crm/appointments              (موجود ✅)
  ├── الأنشطة                ← /crm/activities                (موجود ✅)
  ├── المتابعات              ← /crm/follow-ups                (موجود ✅)
  ├── الرسائل والإشعارات     ← /crm/messages                  (موجود ✅)
  ├── سجل التفاعلات          ← /crm/timeline                  (موجود ✅)
  ├── بوابة العميل           ← /crm/portal                    (موجود ✅)
  ├── الاشتراكات             ← /crm/subscriptions             (موجود ✅)
  ├── النقاط والأرصدة        ← /crm/credits                   (موجود ✅)
  └── ❌ حذف العملاء          (مكرر — الأصل تحت المبيعات)
```

### 5. وحدة التشغيل (التصنيف الصحيح)

```
التشغيل
  ├── أوامر الشغل           ← ربط بـ ERPNext بدل البيانات التجريبية  ⚠️ إصلاح مطلوب
  ├── تتبع الوقت            ← /operations/time-tracking     (موجود ✅)
  ├── الإيجارات             ← /operations/rentals            (موجود ✅)
  ├── مصروفات الجوال        ← /operations/mobile-expenses    (موجود ✅)
  ├── ❌ حذف حضور ESS للجوال  (مكرر — الأصل تحت HR)
  ├── ❌ حذف جرد المخزون بالجوال (مكرر — الأصل تحت المخزون)
  └── ❌ إعادة تصميم دورات العمل (بدل البيانات التجريبية)
```

## الخلاصة

| المؤشر | القيمة |
|--------|--------|
| **عدد الشاشات المكررة** | 6 شاشات |
| **عدد الشاشات المصنفة خطأ** | 4 شاشات |
| **عدد الشاشات الوهمية** | 4 شاشات |
| **إجمالي المشاكل** | 14 مشكلة تصنيف |
| **الجهد التقديري للإصلاح** | 3-5 أيام عمل |

المشكلة الجوهرية هي أن النظام صُمم بمنطق **"النوع المحاسبي"** (Sales Invoice = مستند محاسبي) بدلاً من منطق **"دورة العمل"** (Sales Invoice = عملية بيع). هذا المنطق يتعارض تماماً مع كيفية عمل أنظمة ERP الاحترافية مثل دفتره، حيث الفاتورة تنشأ من وحدة المبيعات/المشتريات وتتدفق تلقائياً إلى المحاسبة.
